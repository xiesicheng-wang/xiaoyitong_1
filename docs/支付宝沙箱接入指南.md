# 支付宝沙箱接入指南（钱包充值）

> 现状：`WalletService.recharge()` 是模拟充值。本文档描述接入支付宝沙箱的完整路径，
> 预计半天工作量。密钥需要你自己注册获取，**绝不能提交到 git**。

## 一、开通沙箱（你需要做的）

1. 登录 [支付宝开放平台](https://open.alipay.com)（用你自己的支付宝账号）
2. 控制台 → 研发服务 → **沙箱环境**，获得：
   - 沙箱 **APPID**（90 开头）
   - 沙箱**买家账号**（xx@sandbox.com + 登录密码，用于付款测试）
3. 自研应用页面 → 接口加签方式选 **公钥模式**，用 [密钥工具](https://opendocs.alipay.com/common/02kipl) 生成：
   - 应用公钥 / 应用私钥（PKCS8，Java 用）
   - 上传应用公钥后获得 **支付宝公钥**
4. 沙箱网关固定为：`https://openapi-sandbox.dl.alipaydev.com/gateway.do`

## 二、依赖与配置

`pom.xml` 已预留（接入时取消注释）：

```xml
<dependency>
    <groupId>com.alipay.sdk</groupId>
    <artifactId>alipay-sdk-java</artifactId>
    <version>4.39.x</version> <!-- 接入前查 Maven 最新版 -->
</dependency>
```

`application.yml` 追加（真实值走环境变量，与 MYSQL_PASSWORD 同款做法）：

```yaml
youlinbang:
  alipay:
    app-id: ${ALIPAY_APP_ID:}
    private-key: ${ALIPAY_PRIVATE_KEY:}
    alipay-public-key: ${ALIPAY_PUBLIC_KEY:}
    gateway: https://openapi-sandbox.dl.alipaydev.com/gateway.do
    notify-url: ${ALIPAY_NOTIFY_URL:}   # 内网可用内网穿透（如 natapp）暴露
```

## 三、代码挂点（已设计好，接入即填）

支付通道抽象在 `WalletService` 层面：

```
前端"充值" → POST /api/wallet/recharge
             └─ 当前：直接调 recharge()（模拟）
             └─ 接入后：改为创建支付单 → 返回支付宝收银台 URL
                        支付宝异步回调 /api/wallet/alipay/notify → 验签 → recharge() 入账
```

新增 `AlipayService`：
1. `createPay(userId, amount)` — 用 `AlipayClient` 生成 `alipay.trade.page.pay` 表单/跳转串，
   记录一张 `t_payment`（订单号、金额、状态=待支付）；
2. `/api/wallet/alipay/notify` 回调端点（**免登录白名单**）：
   - 验签（用支付宝公钥）→ 校验金额与支付单一致 → 调 `walletService.recharge()` → 返回 "success"；
3. 幂等：支付宝会重复回调，`t_payment` 状态机（待支付→已支付）保证不重复入账。

## 四、安全红线（论文与答辩都会问）

- 应用私钥只存环境变量，**不进代码库**
- 回调必须验签 + 校验金额，否则任何人都能伪造"充值成功"
- 回调幂等（重复通知只入账一次）
- 沙箱验证通过后，换正式网关 + 正式密钥即切生产

## 五、验收清单

- [ ] 沙箱买家付款成功，钱包余额增加对应金额
- [ ] t_payment 状态流转 待支付 → 已支付
- [ ] 伪造回调（无签名/金额篡改）被拒绝
- [ ] 重复回调只入账一次
